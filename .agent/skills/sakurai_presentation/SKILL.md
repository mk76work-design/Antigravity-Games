# Sakurai Presentation スキル

桜井政博氏の知見に基づく、**ゲームの「見せ方」と「演出」** のガイドライン。
グラフィック、サウンド、UIの実装時に本スキルを参照し、演出の質を担保する。

## 1. グラフィック / ビジュアル設計

### 光を描く（F-1）

> 物質の色そのものより、光の当たり方や反射を重視する。

- オブジェクトの「固有色」だけでなく、**環境光・反射光・影**を意識する
- ハイライトとシャドウのコントラストで立体感を出す
- 暗い背景に明るいオブジェクト（または逆）で視線を誘導する

### 判定の強調（F-2）

> ゲーム上で重要なオブジェクトや当たり判定を視覚的に目立たせる。

| 対象 | 強調方法 |
|------|---------|
| プレイヤーキャラ | 背景と異なる彩度・明度、アウトライン |
| 敵の弾 / 攻撃範囲 | 高彩度の警告色（赤、オレンジ）、点滅 |
| アイテム / 収集物 | 光彩エフェクト、パルスアニメーション |
| 当たり判定 | ゲーム的に重要な判定は小さめに見せすぎない |

### 視認性優先の原則

- **過剰な背景ディテール** は NG — プレイヤーのアクション視認性を最優先する
- キャラクターが背景に埋もれないよう、表示レイヤーの優先度を管理する
- エフェクトでキャラが見えなくならないよう注意する

## 2. エフェクト設計

### メリハリのある構成（H-1）

> 加算エフェクト（光のボケ）だけに頼らず、「芯」を持つエフェクトを作る。

```
❌ NG: 全て加算エフェクト → 画面が白飛び

✅ OK: 構成パターン
  [不透明な芯（ポリゴン/ベタ塗り)] ← メリハリの核
       ＋
  [加算エフェクト（光彩・ブルーム）]  ← 装飾
```

### エフェクトと視認性の両立

- キャラクター周辺のエフェクトは**透明度**を調整する
- エフェクトの表示優先度をキャラクターより下に設定する
- 画面全体が白飛びしないよう、エフェクトの **密度** を管理する

## 3. サウンド設計

### 音の優先度設計（I-1）

> プレイヤーにとって重要なイベントほど音量を大きくする。

| 優先度 | カテゴリ | 音量目安 |
|-------|---------|---------|
| **最優先** | ダメージ、撃墜、重要イベント | 100% |
| **高** | 攻撃ヒット、アイテム取得 | 70-80% |
| **中** | 通常操作SE（ジャンプ、移動） | 50-60% |
| **低** | 環境音、BGM | 30-50% |
| **最低** | 遠方の効果音 | 10-20% |

### 誇張されたSE（I-2）

> リアルな音よりも、**わざとらしいほど派手な音** がゲームの手応えを生む。

- 打撃音：「ペチン」→「ドカッ」に誇張する
- 爆発音：小さな爆発でも存在感のある音にする
- 収集音：気持ちよい「キラン」「シャキーン」系の音で報酬感を演出する

### BGMの統一感（I-3）

- メインテーマのアレンジを使い回すと一貫した印象を与えられる
- バリエーションで飽きを防ぎつつ、メモリ効率も高まる

### チープ環境での検証（I-4）

- 高級スピーカーだけでなく、**安価なスピーカー・イヤホン** で音割れや聞こえ方を確認する
- 低音域が抜ける環境でも重要なSEが聞こえるか検証する

## 4. UI / ユーザーインターフェース設計

### 右脳的処理の優先（J-1）

> 文字を読ませる前に「色」や「絵」で直感的に判断させる。

| 手法 | 例 |
|------|-----|
| **色分け** | メニューカテゴリごとに異なるカラーテーマ |
| **アイコン** | テキストラベルよりアイコンを優先 |
| **サイズ** | 重要なボタンは物理的に大きく |
| **形状** | 円形（決定）/ 角型（キャンセル）など直感に沿う |

### 文字サイズの配慮（J-2）

- 文字サイズは基本「**大きめ**」に設定する
- モバイル環境や小型画面でのプレイを想定する
- HUDサイズの変更オプションを提供する

### アクセシビリティ（J-3）

実装すべきアクセシビリティ機能：

- [ ] HUDサイズの変更
- [ ] 色彩調整（色覚特性への配慮）
- [ ] 操作キーのカスタマイズ
- [ ] 画面振動の強弱調整 / OFF設定
- [ ] 激しい画面動きがある場合、酔い対策（中央ドット等）

### UI の NG パターン

| NG | 理由 |
|----|------|
| 文字主体のUI | 説明を読まないと理解できないUIはテンポを損なう |
| 酔い対策の不在 | 激しい動きにはプレイヤーへの配慮が必須 |
| 全情報の均一表示 | 重要 / 非重要の差が視覚で伝わらない |

## エージェントへの実装チェックリスト

### ビジュアル
- [ ] オブジェクトの**視認性**が背景に対して確保されているか
- [ ] ゲーム的に重要な要素が**視覚的に強調**されているか
- [ ] エフェクトに**メリハリ（芯＋装飾）**の構成があるか
- [ ] エフェクトがキャラの視認性を妨げていないか

### サウンド
- [ ] SEに**優先度の階層**が設計されているか
- [ ] ヒット音やイベント音が**十分に誇張**されているか
- [ ] **低品質な環境**でも重要なSEが聞こえるか

### UI
- [ ] UIが**文字ではなく色・アイコン**で直感的に理解できるか
- [ ] 文字サイズが**十分に大きい**か
- [ ] **アクセシビリティ**オプションが含まれているか
