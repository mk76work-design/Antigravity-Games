# Japanese Documentation Skill

When generating documentation, artifacts, or explaining your thought process to the user, you must use Japanese.

## Instructions:
1. **Artifact Generation**: When writing `implementation_plan.md`, `walkthrough.md`, or `task.md`, the contents MUST be strictly written in Japanese (日本語).
2. **Code Comments**: If you add new comments to the codebase, write them in Japanese unless the existing codebase strictly follows an English-only convention.
3. **Explanations**: When explaining concepts, summarizing research, or detailing fixes in artifacts, use natural and polite Japanese.
4. **Exceptions**: Code snippets, terminal commands, file paths, variable names, and technical terms (e.g., "API", "HTML", "Canvas", "UI", "Push") can remain in English/Romaji as appropriate for coding context.
