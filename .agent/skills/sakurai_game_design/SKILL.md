## 1. 面白さの設計原則

### リスクとリターンの法則（B-1）

> 「ゲーム性」とは「リスクとリターン」および「駆け引き」である。

すべてのゲームメカニクスに以下を適用する：

| 要素 | 説明 | 確認事項 |
|------|------|---------|
| **リスク** | プレイヤーが負う代償（HP消費、タイム消費、ミスの可能性） | リスクが存在するか？ |
| **リターン** | リスクに見合う報酬（スコア、アイテム、進行） | リターンがリスクに比例しているか？ |
| **選択** | プレイヤーが自らリスクを取るかどうかを「選べる」こと | プレイヤーに選択権があるか？ |

**適用例：**
- スペースインベーダー：前に出れば命中率↑（リターン）、被弾リスク↑（リスク）
- 悪魔の釜（パルテナの鏡）：自ら難易度を上げると報酬が増加

### ギュッとしてパッと解消（B-2）

「溜め」→「解放」のサイクルで快感を生む設計パターン：

```
[緊張フェーズ]  →  [解放フェーズ]
   溜め操作         一気に解放
   危険な状況        安全の確保
   制限された行動      自由な行動
```

**実装時のチェック：**
- [ ] ゲーム内に「溜め→解放」のサイクルが存在するか
- [ ] プレイヤーが「解放」の瞬間に達成感を感じられるか

## 2. プレイヤー体験の設計

### とにかくゲームさせてみて（C-1）

> 仕様を理解させる最も早い方法は「体験」させること。

- 長いチュートリアルテキストやカットシーンでプレイヤーを待たせない
- 操作を「説明する」のではなく「触らせて学ばせる」
- ゲーム開始後、**最短時間**でプレイヤーにコントロールを渡す

### 目の前に吊られたごほうび（C-2）

> 常に「あと少しで手が届く目標」を可視化する。

- [ ] 次の報酬・目標がプレイヤーに常に見えているか
- [ ] 進捗感を視覚的にフィードバックしているか（ゲージ、スコア、距離表示）
- [ ] 報酬までの距離が「近すぎず遠すぎない」適切な間隔か

### ワンボタンのマルチコンテキスト（C-3）

入力をシンプルに保ちつつ、奥深さを出す：

| 方法 | 例 |
|------|-----|
| 押す長さ | 短押し：ジャブ / 長押し：強攻撃 |
| タイミング | ジャストガード、パリィ |
| 状況 | 地上：通常攻撃 / 空中：空中攻撃 |

## 3. コンセプト立案

### 課題解決のロジック（N-1）

ゲーム企画は「思いつき」ではなく、**課題→解決**のロジックで立案する：

```
1. 現状の課題を特定する
   例: 「既存の格闘ゲームはコマンド入力が複雑で初心者が遊べない」

2. 解決策をコンセプトにする
   例: 「方向＋ボタンだけで全技が出る直感的操作」→ スマブラ

3. そのコンセプトが新しい面白さを生むか検証する
```

### ターゲットに応じた設計（N-2）

| ターゲット | 設計方針 | 例 |
|-----------|---------|-----|
| 初心者 | ミスの救済措置を充実 | カービィの飛行（落下ミス救済） |
| 上級者 | 遊びの幅・やり込み要素 | コピー能力の多様性 |
| 全対象 | 「入口は広く、奥は深く」 | スマブラの蓄積ダメージシステム |

## 4. 分析手法：分解、考察、再構築（C-4）

参考ゲームを分析する際のフレームワーク：

1. **分解**: ゲームの要素を個別に分解する（操作、報酬、リスク、テンポ…）
2. **考察**: 各要素が「なぜ面白いのか」を論理的に説明する
3. **再構築**: 自分のゲームに応用可能な形に再構築する

---

## 5. NG（非推奨）パターン

| NG | 理由 |
|----|------|
| リスクのない勝利 | ゲーム性（面白さ）が消失する |
| リターンのないリスク | プレイヤーのモチベーションが喪失する |
| 長いチュートリアル | プレイヤーは「遊ぶ」ために来ている |
| 悪いおつかい | 道中に変化がなく、報酬が見合わない移動 |
| 目的のない斬新さ | 何の課題も解決しない企画は独りよがり |
