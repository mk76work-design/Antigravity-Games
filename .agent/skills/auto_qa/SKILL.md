# Auto QA スキル

ゲーム実装後の品質保証（QA）を自動化するためのスキル。
ブラウザサブエージェントを活用した動作確認に加え、コード品質の静的分析とセキュリティ検証を行う。

**本スキルは `game_dev_workflow` の Reviewer（検証者）役割に対応する。**

---

## QAテスト実行手順

### Step 1: ゲームの起動
```
1. ゲームの `index.html` をローカルサーバーで起動する
   - 例: `npx -y serve <game-directory>` または `python -m http.server`
2. ブラウザサブエージェントで起動URLにアクセスする
```

### Step 2: 基本動作チェック

| # | チェック項目 | 確認方法 |
|---|------------|---------|
| 1 | ページが正常にロードされる | ブラウザでアクセスしてエラーがないか |
| 2 | 初期画面が正しく表示される | スクリーンショットで目視確認 |
| 3 | ゲームが操作可能 | キーボード/マウス入力で反応するか |
| 4 | コンソールエラーがない | DevToolsのコンソールを確認 |
| 5 | ゲームオーバー/クリア処理が動く | 条件を満たしてテスト |
| 6 | リトライ/再スタートが機能する | ゲームオーバー後のボタン動作 |

### Step 3: レスポンシブ確認
```
1. デスクトップサイズ (1920x1080) でスクリーンショット
2. タブレットサイズ (768x1024) でスクリーンショット
3. モバイルサイズ (375x667) でスクリーンショット
```

### Step 4: パフォーマンス確認
```
1. ゲームプレイ中のFPSを確認（可能であれば）
2. メモリリークの兆候がないか確認（長時間プレイ）
3. アセットの読み込み時間を確認
```

## Step 5: コード品質の静的分析（アーキテクチャ負債チェック）

> コード品質の基準は [`engine_rules` スキル](file:///c:/Users/pusap/work/Antigravity-Games/.agent/skills/engine_rules/SKILL.md) に一元管理されている。
> ここでは QA 固有の **検出方法** のみを定義する。

### 5-1. 自動検出コマンド

| チェック項目 | 検出方法 |
|------------|---------|
| ファイル行数超過（300行） | `wc -l` または行数カウント |
| `var` キーワードの使用 | `grep "var "` |
| グローバル変数 | ファイル先頭の `var ` 宣言を検索 |
| `console.log` デバッグ残り | `grep "console.log"` |
| マジックナンバー | コードレビューで確認 |

### 5-2. Webゲーム固有のアンチパターン検出

- [ ] `requestAnimationFrame` の停止忘れ（メモリリーク）
- [ ] イベントリスナーの解除忘れ（メモリリーク）
- [ ] `new` オブジェクト生成がゲームループ内にある（GC負荷）
- [ ] ネストが4段階以上の制御構文

## Step 6: セキュリティチェック

> AI生成コードの約40%に脆弱性が含まれるという調査結果がある。
> 以下のチェックでWebゲーム特有のセキュリティリスクを検出する。

### セキュリティチェックリスト

| # | チェック項目 | リスク | 検出方法 |
|---|------------|-------|---------|
| 1 | `eval()` の使用 | 任意コード実行 | `grep "eval("` |
| 2 | `innerHTML` への未検証データ挿入 | XSS | `grep "innerHTML"` |
| 3 | `document.write()` の使用 | XSS | `grep "document.write"` |
| 4 | 外部URLからのスクリプト読み込み（バージョン未固定） | サプライチェーン攻撃 | `grep "script src="` でバージョン確認 |
| 5 | `localStorage` への機密データ保存 | データ漏洩 | `grep "localStorage"` |
| 6 | ユーザー入力の未サニタイズ処理 | インジェクション | コードレビュー |

## QAレポートの生成

テスト完了後、`templates/qa_report_template.md` を使ってQAレポートを生成する。

### レポート出力先
- プロジェクトの artifacts ディレクトリ（例: `brain/<conversation-id>/qa_report.md`）
- または、ゲームディレクトリ直下に `QA_REPORT.md` として配置

### スクリーンショットの添付
- ブラウザサブエージェントの動画レコーディング機能を活用
- 重要な画面状態はスクリーンショットとしてキャプチャ
- レポートに埋め込む際は `![説明](パス)` 形式を使用

## エージェントへの指示

### テスト実行時のプロンプト例
```
以下のゲームのQAテストを実行してください：
1. ローカルサーバーを起動: npx -y serve <game-dir>
2. ブラウザでアクセスし、基本動作を確認
3. コード品質の静的分析を実施（300行ルール、アンチパターン検出）
4. セキュリティチェックを実施（eval、innerHTML、XSS等）
5. デスクトップ・タブレット・モバイルサイズでスクリーンショットを撮影
6. QAレポートを生成
7. 発見した問題を LESSONS_LEARNED.md に差分追記
```

## 既知のチェック観点

### Webゲーム共通の問題パターン
- Canvas要素のサイズが画面サイズと不一致
- `requestAnimationFrame` のリーク（画面遷移時に停止していない）
- イベントリスナーの重複登録
- モバイルでのタッチイベント未対応
- Audio の自動再生ブロック（ユーザーインタラクション前の再生）
- `setInterval` ベースのゲームループ（`requestAnimationFrame` を使うべき）
- フレームレート依存の物理計算（deltaTime未使用）
- ゲームループ内での `new` によるオブジェクト生成（オブジェクトプールを使うべき）
