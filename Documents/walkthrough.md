## 1. 新しいゲームを作る

### Step 1: 企画を伝える

エージェントにゲームの概要を伝えます。以下の情報があるとスムーズです。

| 項目 | 例 |
|------|-----|
| ジャンル | パズル、アクション、シューティング等 |
| 参考ゲーム | 「テトリスのような」「スマブラ風の」 |
| 操作方法 | キーボード / マウス / タッチ |
| 特徴・こだわり | 「水が溜まるギミック」「ステージ制」等 |

**プロンプト例:**
```
「テトリスに水風船の要素を加えたパズルゲームを作ってください。
水位が上がるメカニクスを入れたいです。キーボード操作で。」
```

> ⚠️ エージェントはいきなりコードを書かず、まず**設計計画書** (`implementation_plan.md`) を出力します。
> これは意図的な動作です（Vibe Coding 防止）。

### Step 2: 設計計画書をレビューする

エージェントが提示する計画書を確認し、承認または修正を指示します。

**確認ポイント:**
- [ ] ゲームのコンセプトが自分のイメージと合っているか
- [ ] ファイル構成が適切か（1ファイル300行以内が原則）
- [ ] 技術スタックに問題がないか

**応答例:**
- 問題なし → `「LGTM」` または `「進めてください」`
- 修正あり → `「操作はマウスではなくキーボードにしてください」`

### Step 3: 実装完了を待つ

承認後、エージェントが実装を進めます。完了すると以下が生成されます：

| 生成物 | 場所 |
|--------|------|
| ゲーム本体 | `<ゲーム名>/index.html`, `main.js` 等 |
| 構造ドキュメント | `<ゲーム名>/docs/PROJECT_STRUCTURE.md` |
| コードマップ | `<ゲーム名>/docs/REPO_MAP.md` |
| 教訓記録 | `<ゲーム名>/docs/LESSONS_LEARNED.md` |
| ゲーム一覧 | ルート直下 `GAME_REGISTRY.md`（更新） |

## 2. 既存のゲームを修正・改良する

### バグ修正を依頼する

```
「WaterBalloonTetris のブロックが落下しなくなるバグを修正してください。」
```

### 機能追加を依頼する

```
「WaterBalloonTetris にハイスコア保存機能を追加してください。」
```

### 大規模な改修を依頼する

```
「WaterBalloonTetris を全面リファクタリングして、
main.js が300行を超えているので分割もお願いします。」
```

> エージェントは作業開始前に `docs/` 内のドキュメントを読み込み、
> 過去の教訓や現在の構成を把握してから作業を始めます（Context Sync プロトコル）。
> 作業完了後はドキュメントを自動更新します（State Persistence プロトコル）。

## 3. 品質チェック（QA）を依頼する

### 基本的なQA依頼

```
「WaterBalloonTetris のQAテストを実行してください。」
```

エージェントは以下を自動的に実施します：

| チェック | 内容 |
|---------|------|
| 動作確認 | ブラウザで起動、操作テスト、コンソールエラー確認 |
| レスポンシブ | デスクトップ / タブレット / モバイルサイズでスクリーンショット |
| コード品質 | ファイル行数、グローバル変数、デバッグログ残り |
| セキュリティ | `eval()`, `innerHTML`, XSS リスク |

**成果物:** `QA_REPORT.md`（スクリーンショット付き）

## 5. 付録: プロジェクト構成

### ディレクトリ構造

```
Antigravity-Games/
├── .agent/skills/              ← AI スキル定義（編集不要）
│   ├── game_dev_workflow/      ← 開発フロー定義
│   ├── project_analyzer/       ← ドキュメント自動生成スクリプト
│   ├── auto_qa/                ← 自動QAチェック定義
│   ├── engine_rules/           ← コード品質ルール
│   ├── sakurai_game_design/    ← ゲーム設計原則（桜井政博氏）
│   ├── sakurai_game_feel/      ← 操作感・手応え実装ガイド
│   ├── sakurai_presentation/   ← 演出・UI・サウンド設計ガイド
│   └── japanese_documentation/ ← 日本語ドキュメント設定
│
├── GAME_REGISTRY.md            ← 全ゲーム一覧（自動生成）
│
├── WaterBalloonTetris/         ← ゲームプロジェクト
│   ├── docs/                   ← プロジェクト固有ドキュメント
│   │   ├── PROJECT_STRUCTURE.md
│   │   ├── REPO_MAP.md
│   │   └── LESSONS_LEARNED.md
│   ├── index.html
│   ├── main.js
│   └── ...
│
└── Documents/                  ← リサーチ・手順書
    └── walkthrough.md          ← この手順書
```

### スキル一覧の概要

| カテゴリ | スキル名 | 役割 |
|---------|---------|------|
| **開発基盤** | Game Dev Workflow | 計画→実装→検証の標準フロー |
| **開発基盤** | Project Analyzer | ドキュメント自動生成・更新 |
| **開発基盤** | Japanese Documentation | 日本語での記述を保証 |
| **品質管理** | Auto QA | ブラウザテスト・コード静的分析 |
| **品質管理** | Engine Rules | コード品質ルール（300行制限等） |
| **デザイン** | Sakurai Game Design | リスクとリターン、報酬設計 |
| **デザイン** | Sakurai Game Feel | ヒットストップ、先行入力、画面振動 |
| **デザイン** | Sakurai Presentation | グラフィック・サウンド・UI演出 |
